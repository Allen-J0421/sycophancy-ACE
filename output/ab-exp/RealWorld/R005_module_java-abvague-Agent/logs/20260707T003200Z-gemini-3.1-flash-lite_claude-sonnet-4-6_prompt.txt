=== Turn 1 ===
Extract the hardcoded species configuration logic from `Initializer.java` and move it into a dedicated `SpeciesFactory` class to decouple the simulation initialization from the creation logic.

=== Turn 2 ===
Extract the `FieldView` inner class from `SimulatorView.java` into a standalone class `FieldView.java` and encapsulate the rendering logic, delegating field-drawing responsibilities to this new component.

=== Turn 3 ===
Refactor `FieldStats.java` by extracting the responsibility of traversing the `Field` and counting species into a new `FieldAnalyzer` class, and modify `FieldStats` to consume this analyzer rather than performing the traversal itself.

=== Turn 4 ===
Extract the hardcoded configuration for climate scenarios out of the `ClimateScenarios` enum and move it into a `ClimateScenarioFactory` that reads the scenarios from a new `scenarios.csv` file, making the simulation configuration more data-driven.

=== Turn 5 ===
Extract the `CSVReader` logic into a single `ConfigurationLoader` utility or strategy class that centralizes file I/O and parsing, replacing the scattered inheritance-based `CSVReader` approach in `AnimalCSVReader`, `HabitatCSVReader`, `PlantCSVReader`, and `ClimateScenarioFactory`.

=== Turn 6 ===
Refactor the `Simulator` class to separate the "simulation step" execution logic from the `Simulator` class into a new `SimulationController` class, allowing `Simulator` to focus on managing the collection of `Species`, the `Field`, and the UI coordination, thereby adhering to the Single Responsibility Principle.

=== Turn 7 ===
Refactor `Habitat` by extracting the seasonal management logic (temperature randomization and seasonal transitions) into a dedicated `SeasonManager` class, allowing `Habitat` to act purely as a coordinator of the simulation's climate state.

=== Turn 8 ===
Refactor `Animal.java` by extracting the movement, reproduction, and food-searching logic into a `MovementStrategy` or similar set of classes, delegating these distinct behavioral responsibilities away from the `Animal` class itself to follow the Strategy pattern and simplify the `act()` method.

=== Turn 9 ===
Refactor the `GUIHandler` by extracting its view-switching and simulation-launching logic into a `SimulationCoordinator` class, and modify `GUIHandler` to act solely as the event listener and UI manager, effectively separating UI event handling from the orchestration of the simulation life cycle.

=== Turn 10 ===
Refactor `SimulatorView.java` by extracting the GUI layout and button creation logic for the simulation view into a dedicated `SimulationViewLayout` class, so that `SimulatorView` focuses on its primary task of displaying simulation status.
