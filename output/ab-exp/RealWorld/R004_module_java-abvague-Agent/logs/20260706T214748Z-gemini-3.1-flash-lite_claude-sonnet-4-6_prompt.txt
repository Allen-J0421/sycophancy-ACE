=== Turn 1 ===
The `Simulator` class is currently handling too many responsibilities, including managing the simulation lifecycle, controlling the environment state, handling GUI listeners, and manually orchestrating the population generation logic. This makes the class difficult to maintain and test.

Please refactor the `Simulator` class by extracting the responsibility of simulation step execution and population management into a separate `SimulationOrchestrator` or a similar dedicated service class, leaving `Simulator` to act primarily as the entry point and controller for the GUI.

=== Turn 2 ===
The `populate()` method in `SimulationOrchestrator` is a long, monolithic block of imperative code that manually checks every single class type when spawning organisms. This violates the Open/Closed Principle and makes adding new species tedious.

Please refactor the population logic by introducing a strategy pattern or a factory-based approach where each species (or a registry of species) defines how it should be instantiated and added to the field, allowing the orchestrator to populate the simulation in a data-driven way.
